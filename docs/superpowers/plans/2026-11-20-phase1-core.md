# Galleon Customizer — Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A daemon, `galleon-customizerd`, that drives the Galleon 100 SD Stream Deck module itself (replacing GalleonCore's `galleond`), renders keys and the LCD strip, and runs every built-in action from a JSON profile. It is usable by editing JSON; the editor comes in phase 2.

**Architecture:** Python package `galleon_customizer`. A pure protocol layer turns bytes into events and images into reports. A device layer does the HID I/O. A config model loads and validates profiles. A renderer draws keys and the strip with Pillow. An action registry holds the built-in actions. An engine maps events to actions. The service ties them together on a GLib main loop with a session D-Bus interface. Desktop-specific code (GNOME) sits behind `desktop.Backend`.

**Tech Stack:** Python ≥ 3.12, PyGObject (GLib/Gio), `python3-hid` (hidapi bindings, `import hid`), Pillow, python-evdev, pytest; Ubuntu 24.04+ packages only.

**Spec:** `docs/superpowers/specs/2026-11-20-galleon-customizer-design.md`

## Global Constraints

- Targets GNOME on Wayland, Ubuntu 24.04 or newer; desktop-specific code only in `galleon_customizer/desktop/`.
- App ID `io.github.galleon_customizer.GalleonCustomizer`; D-Bus name and interface `io.github.galleon_customizer.GalleonCustomizer1`, object path `/io/github/galleon_customizer/GalleonCustomizer1`.
- Commands: `galleon-customizerd` (daemon). Config dir `~/.config/galleon-customizer/`; plugins dir (phase 3) `~/.local/share/galleon-customizer/plugins/`.
- Never open or write to the keyboard part `1b1c:2b0c`. Only `1b1c:2b18`, HID interface 0.
- No root at run time; udev `uaccess` rules for `2b18` and `/dev/uinput`.
- Profiles are JSON with `"schema_version": 1`; writes are atomic (temp file + rename); a migrated file keeps `<name>.bak`.
- User-visible strings are English source strings wrapped in `_()` (gettext domain `galleon-customizer`); Vietnamese `.po` ships in `po/vi.po`.
- Licence GPL-3.0-or-later; SPDX header in every source file.
- Commit identity is the repo's local one ("Galleon Customizer"); no personal data in files.

## Review Focus

- The module is unplugged mid-write or the PC resumes from suspend: the daemon must reconnect within 2 s of replug and redraw everything, not crash or leave blank keys (Task 3, Task 11).
- A profile file with a syntax or schema error: the daemon keeps the last good profile, logs the error with file/line, and shows an error notification; it never blanks the keys (Task 4, Task 11).
- An action that hangs (a command that never exits, a portal dialog left open): key input, dials and keep-alive keep working; other keys still respond (Task 6, Task 10).
- `galleond` or a second daemon already holds the device: the daemon exits with a clear message naming the other process instead of fighting over the device (Task 11).
- Fast dial turns (many steps in one report) and a key pressed during a page switch: one page per detent for page navigation, volume steps summed, no action fired on the wrong page (Task 10).

**Files:**

- Test: `tests/device/test_protocol.py`

**Interfaces:**
- Produces (in `galleon_customizer.device.protocol`):
  - constants `VENDOR_ID = 0x1B1C`, `PRODUCT_ID = 0x2B18`, `INTERFACE = 0`, `KEY_COUNT = 12`, `KEY_COLUMNS = 3`, `KEY_ROWS = 4`, `DIAL_COUNT = 2`, `KEY_IMAGE_SIZE = 160`, `SCREEN_WIDTH = 720`, `SCREEN_HEIGHT = 384`, `KEEP_ALIVE_MS = 500`, `MAX_DIAL_STEPS = 32`, `MAX_JPEG_SIZE = 4 * 1024 * 1024`, `OUTPUT_REPORT_SIZE = 1024`, `FEATURE_REPORT_SIZE = 32`, `FIRMWARE_REPORT_ID = 0x05`
  - event dataclasses (frozen): `KeyEvent(key: int, pressed: bool)`, `DialPressEvent(dial: int, pressed: bool)`, `DialTurnEvent(dial: int, steps: int)`
  - `InputState` (mutable: `keys: list[bool]`, `dials: list[bool]`)
  - `decode_input(report: bytes, state: InputState) -> list[Event] | None` — `None` means invalid (state unchanged); `[]` means ignored/no change
  - `keep_alive_report() -> bytes`, `brightness_report(percent: int) -> bytes | None`, `dial_ring_reports(dial: int, rgb: tuple[int, int, int]) -> list[bytes]`
  - `key_image_reports(key: int, jpeg: bytes) -> list[bytes]`, `screen_image_reports(jpeg: bytes, x: int, y: int, w: int, h: int) -> list[bytes]`
  - `parse_firmware(report: bytes) -> str`

Report layouts (from GalleonCore `lib/include/galleon/Protocol.h`, galleon-deck `docs/PROTOCOL.md`):
- Input, report ID 1, 512 bytes: keys `01 00 <0x000C u16le> <12 bytes 0/1>`; dials `01 03 <0x0003 u16le> <kind> <d0> <d1>`, kind 0 = buttons (0/1), kind 1 = rotation (signed int8 steps). Invalid: wrong count, key/button byte not 0/1, |steps| > 32, too short.
- Feature reports are 32 bytes, zero-padded: keep-alive `03 27`; brightness `03 08 <0..100>`; dial ring, one report per LED, `03 24 <led> <r> <g> <b>` with `led = (1 - dial) * 4 + segment`, segments 0..3.
- Key image: output reports of 1024 bytes, header `02 07 <key u8> <last u8> <len u16le> <part u16le>`, then ≤ 1016 JPEG bytes, zero-padded.
- Screen image: header (16 bytes) `02 0c <x u16le> <y u16le> <w u16le> <h u16le> <last u8> <part u16le> <len u16le> 00`, then ≤ 1008 JPEG bytes, zero-padded. Rectangle must lie inside 720 × 384.
